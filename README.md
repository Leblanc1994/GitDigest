# 日报引擎

一个本地 React 网页工具：选择一个或多个本地 Git 项目，按日期生成可编辑的日报或周报。代码和 Git 数据不会离开电脑。

## AI 整理（可选）

报告栏的“AI 整理”默认开启。填写兼容 Responses API 的 `Base URL` 和 `API Key` 后，它会将本次报告涉及的**项目名、分支名、提交标题、提交日期和最多 30 个变更文件路径**发送给对应的 AI 服务，用于合并重复事项并生成更自然的概览和后续建议；不会保存报告或提交数据，也不会上传完整代码或 diff。

Base URL 默认是 `https://api.openai.com/v1`，也可替换为兼容服务的地址。Base URL 和 API Key 只保存在当前页面/应用会话的内存中，关闭或刷新后会清除。未填写或 AI 服务失败时，应用会保留原有的本地 Git 汇总初稿。

可选：用 `OPENAI_MODEL` 指定模型；未设置时使用 `gpt-5.4`。

## 启动

```bash
npm start
```

浏览器打开终端显示的地址（默认是 `http://127.0.0.1:4173`）。

## 桌面版

桌面版使用 Tauri，运行时不需要启动 `server.js`，前端会直接调用本机 Git。开发预览：

```bash
npm run tauri:dev
```

生成当前操作系统的安装包：

```bash
npm run tauri:build
```

安装包会出现在 `src-tauri/target/release/bundle/` 下。macOS 生成 `.dmg`，Windows 生成 `.exe` 安装包；两者需分别在对应系统上构建。使用桌面版的用户仍需安装 Git。

网页模式和桌面模式共用同一套界面代码：网页模式继续请求本地 Node 服务，桌面模式自动切换为 Tauri 原生命令。

在 macOS 上，“添加项目目录”支持在一个系统窗口中多选文件夹；在 Windows 上会打开原生文件夹选择窗口，选完后可选择继续添加下一个项目。

## Windows 使用要求

- 使用网页模式时：安装 Node.js 20 或以上，并安装 Git。
- 使用桌面安装包时：只需安装 Git，并确保命令行可以执行 `git --version`。
- 网页模式的目录选择依赖 PowerShell（Windows 自带）。

## 当前能力

- 从 macOS 或 Windows 原生目录选择窗口添加多个项目目录
- 只在本机调用 Git，不上传代码
- 按指定日期或所在周读取非合并提交，默认只统计当前 Git 身份的提交
- 统计提交数、变更文件数和当前分支
- 直接编辑、复制或导出 Markdown 报告
- 日报生成后可读取 PMS 工时项目，逐条选择对应项目、编辑工时和工作内容，再确认推送
- 报告优先的工作台布局，并保留可展开的 Git 提交依据

## 推送工时

在日报右上角点击“推送工时”，填写工时系统地址、租户、账号和密码后读取可填报项目。每条日报都需要由用户确认对应的工时系统项目、工时（天）和工作内容；只有点击“确认并推送”才会写入系统。账号密码和访问凭证只用于当前操作，不会写入配置文件或日志；系统也不会覆盖当天已有的工时记录。
